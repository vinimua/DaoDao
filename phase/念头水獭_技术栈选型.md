# 念头水獭 Thought Otter 技术栈选型文档

## 1. 选型结论

念头水獭 V1 推荐采用：

```text
Electron + Vanilla JavaScript + better-sqlite3 + electron-builder
```

核心判断：

> 念头水獭的产品形态与 `clawd-on-desk` 在桌面宠物基础设施层高度重合。对于单人开发来说，Electron 不是最轻的方案，但它是当前最容易参考成熟案例、降低工程风险、快速验证产品需求的方案。

## 2. 项目背景

念头水獭是一个常驻桌面的轻量念头捕捉工具。它不是传统笔记软件，而是通过桌面小水獭完成快速输入、拖拽接收、本地保存和低打扰回顾。

V1 的关键目标不是实现复杂知识库，而是验证：

- 用户是否愿意每天多次把念头递给桌面小水獭
- 快捷输入是否足够低摩擦
- 桌宠反馈是否增强记录意愿
- 本地保存和今日回顾是否足够支撑日常使用

因此，技术栈需要优先服务于：

- 桌面宠物窗口稳定性
- 快捷输入体验
- 透明窗口与点击穿透
- 拖拽交互
- 本地数据可靠性
- 单人开发效率
- 可参考成熟实现

## 3. 最终技术栈

| 层级 | 技术 | 用途 |
| --- | --- | --- |
| 桌面运行时 | Electron | 主进程、窗口管理、托盘、全局快捷键 |
| UI 开发 | HTML / CSS / Vanilla JavaScript | 桌宠渲染、输入框、今日面板、设置页 |
| 本地数据库 | SQLite | 保存 thoughts、settings、events、backups |
| SQLite 访问 | better-sqlite3 | 同步 SQLite 访问，简单稳定，适合本地桌面应用 |
| 配置存储 | JSON + schema 校验 | 保存窗口位置、快捷键、尺寸、回顾时间等 |
| 动画资源 | SVG / GIF / APNG / WebP / PNG | 水獭状态动画 |
| 打包 | electron-builder | Windows 安装包构建 |
| 测试 | Node.js test runner 或 Vitest | 业务服务、分类规则、数据层测试 |
| 日志 | Node fs + 本地 JSONL/text log | 本地运行日志和错误追踪 |

## 4. 为什么选择 Electron

### 4.1 项目形态高度匹配

念头水獭和 `clawd-on-desk` 的相似点非常高：

| 能力 | clawd-on-desk | 念头水獭 |
| --- | --- | --- |
| 常驻桌面宠物 | 有 | 需要 |
| 透明窗口 | 有 | 需要 |
| 点击穿透 | 有 | 需要 |
| 可拖拽移动 | 有 | 需要 |
| 始终置顶 | 有 | 需要 |
| 状态动画 | 有 | 需要 |
| 系统托盘 | 有 | 需要 |
| 设置页 | 有 | 需要 |
| 右键菜单 | 有 | 需要 |
| 多显示器位置处理 | 有 | 需要 |
| Mini / quiet 模式 | 有 | 可参考 |

念头水獭不需要复用它的 AI Agent、Telegram、SSH、WebSocket 等复杂集成，但可以参考它已经验证过的桌宠基础设施。

### 4.2 单人开发更需要成熟案例

如果从零使用 PySide6，需要自己探索：

- 透明窗口
- 点击穿透
- 命中区域
- 置顶恢复
- 全局快捷键冲突
- 拖拽接收
- 多显示器边界
- 托盘菜单
- 动画状态切换

这些问题不是业务核心，但会消耗大量调试时间。

Electron 的优势在于：

- `clawd-on-desk` 已经有大量可参考实现
- HTML/CSS/JS 更适合快速做输入框、气泡、面板和设置页
- Electron 原生提供 `globalShortcut`、`BrowserWindow`、`Tray`、`Menu` 等桌面能力
- 复杂 UI 更容易被 AI 辅助修改

### 4.3 核心差异化更清晰

使用 Electron 后，项目可以把精力集中在真正属于念头水獭的部分：

- 快捷输入框
- 念头保存
- 拖拽文本 / URL / 文件解析
- SQLite 数据结构
- 规则分类引擎
- 今日念头面板
- 悬停预览
- 定时轻回顾
- 本地备份

桌宠窗口、状态切换、托盘和设置这类基础能力可以参考成熟项目的工程设计。

## 5. 与 PySide6 的对比

| 维度 | Electron | Python + PySide6 |
| --- | --- | --- |
| 桌宠窗口案例 | 有成熟参考项目 | 需要更多自研 |
| 透明窗口 | 成熟 | 可做，但需要细调 |
| 点击穿透 | 有参考实现 | 需要结合 Qt / Win32 调试 |
| 全局快捷键 | Electron 原生支持 | 依赖 keyboard / pynput 等库 |
| UI 开发 | HTML/CSS 灵活 | Qt 控件较传统 |
| 动画表现 | 更适合复杂动画和主题 | 基础动画够用，复杂动画较吃力 |
| 本地数据 | better-sqlite3 足够 | sqlite3 很自然 |
| 打包体积 | 较大 | 通常较小 |
| 内存占用 | 较高 | 通常较低 |
| 单人开发可参考性 | 强 | 较弱 |
| AI 辅助开发 | 有现成 JS 项目上下文 | Python 代码生成友好 |

结论：

- 如果只看轻量 MVP，PySide6 有优势。
- 如果看单人开发成功率和成熟案例复用，Electron 更适合当前阶段。

## 6. 不选择 Tauri 的原因

Tauri 具有更低内存占用和更小安装包体积，但 V1 暂不推荐。

原因：

- Rust 增加新的学习和调试成本
- 桌宠窗口、点击穿透、托盘、全局快捷键仍需要平台适配
- 可直接参考的同类成熟项目较少
- AI 辅助开发效率不如 JavaScript / Python 稳定

Tauri 可以作为未来产品化重构选项，但不适合作为 V1 原型首选。

## 7. 不选择 C# WPF / WinUI 的原因

C# WPF / WinUI 对 Windows 原生桌面应用很强，但本项目暂不优先采用。

原因：

- 项目更需要快速原型和成熟桌宠案例参考
- UI 动画和主题系统开发成本不低
- 后续如果考虑跨平台，WPF / WinUI 受限较大
- 与 `clawd-on-desk` 的可参考性不如 Electron

如果未来确定只做 Windows 原生商业工具，可以重新评估 C# 路线。

## 10. V1 最小实现范围

第一阶段只做最小可运行闭环：

1. 启动后显示透明水獭窗口
2. 支持拖动水獭并保存位置
3. 支持右键菜单退出
4. 支持 `Ctrl + Alt + Space` 打开快捷输入框
5. 输入内容后按 Enter 保存到 SQLite
6. 右键打开今日念头面板
7. 重启后数据和位置仍然存在

完成后再迭代：

- 拖拽文本 / URL / 文件
- 接收动画和存储动画
- 悬停气泡
- 定时轻回顾
- 设置页
- 每日备份
- 全屏静默

## 11. 数据层选型

V1 使用 SQLite。

推荐依赖：

```text
better-sqlite3
```

原因：

- API 简单
- 本地桌面应用足够快
- 同步调用便于开发和调试
- 不需要引入 ORM
- 适合 thoughts、settings、app_events、backups 这类轻量表结构

如果后续数据访问复杂，可以再抽象 repository 层，但 V1 不建议过早引入 ORM。

## 12. UI 技术选择

V1 推荐使用 Vanilla JavaScript，不引入 React / Vue。

原因：

- 页面数量少
- 状态复杂度可控
- 更接近 `clawd-on-desk` 的代码结构
- 减少构建链路
- 更容易打包和调试

适合 Vanilla JS 的页面：

- 快捷输入框
- 今日念头面板
- 设置页
- 悬停气泡
- 定时回顾气泡

如果 V2 出现复杂筛选、搜索、批量整理、Markdown 编辑等需求，再考虑引入前端框架。

## 14. 许可证注意事项

`clawd-on-desk` 源码使用 AGPL-3.0，内置美术素材另有版权限制。

建议：

- 可以参考架构、文件拆分和工程思路
- 个人原型阶段可以阅读和实验
- 如果直接复制源码，需要遵守 AGPL-3.0 的开源义务
- 如果未来希望闭源或商业发布，应避免直接复制源码，改为重写同等功能
- 不要直接使用 `clawd-on-desk` 的角色素材和主题素材

## 15. 最终建议

念头水獭 V1 采用 Electron 是合理的。

它不是资源占用最小的选择，但它是当前最适合单人开发、最容易参考成熟桌宠项目、最能把精力集中到产品核心差异化上的选择。

最终推荐：

```text
Electron + Vanilla JavaScript + better-sqlite3 + electron-builder
```

开发策略：

1. 参考 `clawd-on-desk` 的窗口架构和状态机
2. 删除 Agent / Telegram / SSH / PWA 等无关复杂模块
3. 重写念头输入、SQLite 存储、分类、今日面板
4. 先完成 V1 最小闭环，再逐步补齐体验功能
