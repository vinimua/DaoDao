# 念头水獭 Thought Otter AI 开发路线图

## 0. 文档定位

本文档不是给人看的粗略计划，而是给有上下文限制的 AI 编码代理使用的执行路线图。

AI 在开发时必须优先读取：

1. `念头水獭_PRD_Markdown.md`
2. `念头水獭_技术栈选型.md`
3. 本文档 `念头水獭_开发路线图.md`

当上下文不足时，AI 不应重新做产品决策，而应回到本文档中对应阶段继续执行。

## 3. 项目最终完成定义

V1 完成定义：

```text
Windows 用户安装并启动念头水獭后，
能看到常驻桌面的透明小水獭，
可以用 Ctrl + Alt + Space 快速输入念头，
可以拖拽文本、URL、文件给小水獭，
所有念头保存到本地 SQLite，
可以通过右键今日面板查看、复制、删除念头，
悬停和定时轻回顾不打扰当前工作，
重启后数据、窗口位置和设置均恢复正常。
```

V1 完成不是指所有未来功能完成。搜索、Markdown 导出、本地 AI 总结、跨设备同步均属于后续版本。

## 4. 全局工程约束

AI 编码时必须遵守：

1. V1 不引入 React / Vue / Svelte 等前端框架，也不引入 Vite / Webpack 等前端构建链；除非用户明确批准。
2. V1 不引入独立后端进程、HTTP Server、WebSocket Server 或云端服务；业务逻辑运行在 Electron 主进程和本地 service 模块中，通过白名单 IPC 与 renderer 通信。
3. 不上传用户数据。
4. 不读取用户拖入文件的内容，V1 只保存路径。
5. 不用系统通知和声音作为默认反馈。
6. 不把 thought 完整内容写入日志。
7. 不做自动删除，删除使用软删除。
8. 不把业务逻辑塞进 renderer DOM 代码里。
9. 数据库访问集中在 `db.js` 和 service 层。
10. Electron 主进程负责窗口、托盘、快捷键、系统能力。
11. Renderer 负责 UI 展示和用户交互。
12. IPC payload 必须小而明确，不透传任意对象。

## 7. IPC 契约

IPC 名称应稳定，不要随意改名。

| Channel | 方向 | Payload | 返回 |
| --- | --- | --- | --- |
| `thought:create` | renderer -> main | `ThoughtCreateInput` | `Thought` |
| `thought:list-today` | renderer -> main | `{ includeDeleted?: boolean }` | `Thought[]` |
| `thought:delete` | renderer -> main | `{ id: string }` | `{ ok: boolean }` |
| `thought:mark-copied` | renderer -> main | `{ id: string }` | `Thought` |
| `clipboard:write-text` | renderer -> main | `{ text: string }` | `{ ok: boolean }` |
| `otter:set-state` | renderer -> main | `{ state: OtterState, reason?: string }` | `{ ok: boolean }` |
| `window:drag-start` | hit -> main | none | none |
| `window:drag-move` | hit -> main | `{ screenX, screenY }` or none | none |
| `window:drag-end` | hit -> main | none | none |
| `quick-input:show` | main internal | none | none |
| `panel:show-today` | hit/main -> main | none | none |
| `settings:get` | renderer -> main | none | settings snapshot |
| `settings:update` | renderer -> main | partial settings | settings snapshot |

Preload 只暴露白名单 API，不暴露完整 `ipcRenderer`。

## 8. 数据库 Schema

V1 初始 schema：

```sql
CREATE TABLE IF NOT EXISTS thoughts (
  id TEXT PRIMARY KEY,
  content TEXT NOT NULL,
  content_preview TEXT NOT NULL,
  category TEXT NOT NULL,
  source TEXT NOT NULL,
  status TEXT NOT NULL,
  keywords_json TEXT NOT NULL,
  file_path TEXT,
  url TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  reviewed_at TEXT,
  error_message TEXT,
  metadata_json TEXT NOT NULL
);

CREATE INDEX IF NOT EXISTS idx_thoughts_created_at ON thoughts(created_at);
CREATE INDEX IF NOT EXISTS idx_thoughts_status ON thoughts(status);
CREATE INDEX IF NOT EXISTS idx_thoughts_category ON thoughts(category);

CREATE TABLE IF NOT EXISTS settings (
  key TEXT PRIMARY KEY,
  value TEXT NOT NULL,
  updated_at TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS app_events (
  id TEXT PRIMARY KEY,
  event_type TEXT NOT NULL,
  payload_json TEXT NOT NULL,
  created_at TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS backups (
  id TEXT PRIMARY KEY,
  backup_path TEXT NOT NULL,
  status TEXT NOT NULL,
  error_message TEXT,
  created_at TEXT NOT NULL
);
```

## 28. 最重要的开发原则

V1 的优先级：

```text
可记录 > 可回顾 > 不丢数据 > 不打扰 > 可爱 > 可配置 > 可打包
```

不要为了动画、主题、设置、打包提前牺牲核心记录闭环。
